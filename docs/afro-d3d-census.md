# Afro Samurai D3D census

This is a static census of the decoded title executable. It records candidates for native deko3d hooks; it does not enable them. Run the local tools against ignored `out/renut_image.bin`. The extracted image and shader bytes remain outside Git.

Afro uses XDK build **2.0.7776.0**. Its device allocation size `0x5E00`, behavior flags `+0x5DAC`, present interval `+0x351C`, swap count `+0x40B0`, and critical sections `+0x3A60/+0x3A7C` agree with the original reNut/Nuts & Bolts TU3 layout in the read-only `renut-nx` source. Katamari's inherited port changed those values to `0x5700`, `+0x56F8`, `+0x3504`, `+0x4098`, and `+0x3A48/+0x3A64`. This is evidence for restoring the original values **field by field**, not for copying every original offset without inspection. For example, Afro's viewport routine reads surface pointers at `+0x3098` and `+0x30A8`, while the inherited Katamari render-target array begins at `+0x3090` and the original reNut array at `+0x30A0`. Afro's layout differs there from both.

The Afro presentation path reads surface pointers at `+0x39EC/+0x39F0`. Afro's initialization routine writes all three automatic depth/front/back surfaces at `+0x39E8/+0x39EC/+0x39F0`. Do not register CreateDevice, Present, or Swap until all fields touched by their native bodies are audited.

Checked offsets now staged in the native source, with hooks still disabled: allocation `0x5E00`; behavior flags `+0x5DAC`; critical sections `+0x3A60/+0x3A7C`; index buffer `+0x3094` (`0x82348860`); render targets `+0x3098` and depth `+0x30A8` (`0x82348C78`); streams `+0x30AC` and strides `+0x30F0` (`0x823486B8`); textures `+0x3100` (indexed offset `0xC40*4` in `0x82348070`/`0x823480F0`); pixel/vertex shaders `+0x3194/+0x3198` (`0x8234AFA0`/`0x8234B408`); automatic depth/front/back surfaces `+0x39E8/+0x39EC/+0x39F0` (`0x8236E318`). `tools/afro_field_refs.py` finds direct PPC field accesses and `tools/afro_data_refs.py` finds literal function pointers; their hits still require instruction-level interpretation.

The PM4 predication writer `0x82345880` reads `+0x31A4/+0x31A8`; the tiling target comparison in `0x82358C78` reads the current targets at `+0x3098..+0x30A8` and tile targets at `+0x31B8..+0x31C8`. Tiling setup/traversal references `+0x31CC` (count), `+0x32C0` (origins) and `+0x337C` (extent). These constants are staged. The indexed tile-rect array base and command-buffer pointer remain to be verified.

Afro `0x8236E0A8` stores the present interval at `+0x351C`, the behavior flags at `+0x5DAC`, and initializes the default declaration through `0x8234B610`. That helper writes the declaration fields at `+0x2FA0/+0x2FA4`, declaration pointer at `+0x2E2C`, and the same group of default words/bytes at Afro's `+0x2FB8..+0x2FE8`. The matching hard-coded writes in native `InitializeApiState` were moved to those offsets. The larger `0x31A8` snapshot made command buffer replay's last chunk 40 bytes; its NEON tail loads at byte 0, 16 and 24 and stores exactly bytes 0..39. The Switch compiler accepted that change; no replay runtime comparison has reached it yet.

## Render and sampler states

`tools/afro_state_table_scan.py` finds an exact 101-record render table at `0x82865180` and an adjacent 20-record sampler table at `0x82865640`. Each record holds getter, setter, and default words. Render state defaults 10 through 15 are `1, 3, 1, 0, 6, 0`, matching the expected depth, fill, cull, and blend defaults.

`tools/afro_state_map.py` maps the **222 declared state hooks** by state index to Afro getter/setter addresses. All targets are distinct generated function starts: **0 out-of-range indices, 0 missing starts, 0 duplicate targets**. Its `--apply` mode moved all 222 declarations in `hooks/state.cpp`; a second run made zero changes. The report is ignored `out/afro_state_map.txt`. `AFRO_RENUT_HOOKS=OFF` still prevents registration. The state hook implementations still contain Katamari field offsets. The table matches function identity; it does not validate the hook body.

The native state implementation had stale Katamari table addresses `0x82AD8E48/0x82AD9308`, so its device initialization would read unrelated guest memory even with correct hook declarations. Those are now `0x82865180/0x82865640`. PPC accesses from Afro's state setters/getters also established the blend, depth, stencil, point size, sampler limit/filter, viewport, shader and declaration fields in `d3d_native_state.cpp`; the corresponding constants were moved to Afro offsets. Per-state arithmetic and flags still need in-run verification before hooks can be enabled.

`tools/afro_hook_anchors.py` moves individually traced non-table declarations. Besides device creation/presentation, it maps shader binding, indices, streams, viewport, scissor, and depth target calls. `0x82348930` is the indexed render-target setter: it uses `(index + 0xC26) * 4` for device slot `+0x3098 + index*4`, and Present calls it with index zero and the automatic back buffer. The anchor tool validates generated starts and is idempotent. The native bodies still need their own call-shape and field audit before registration.

## Draw path and outstanding checks

The active registration inventory now has 50 individually traced Afro non-table hooks and 222 state-table hooks. `tools/afro_unmapped_hooks.py --apply` disabled 51 inherited Katamari declarations without an Afro identity, including the two raw tiling hooks; its second run changed zero. This prevents those old addresses from overriding unrelated Afro functions in a later renderer-enabled build. It does not establish runtime equivalence of the 272 mapped bodies, so the diagnostic NRO still has `AFRO_RENUT_HOOKS=OFF`.

The game-side draw implementation is at `0x823FB998` (nonindexed) and `0x823FBD88` (indexed). Both flush device state, then write `PM4_DRAW_INDX` (`0xC0012201` for the nonindexed form, `0xC0032201` for the indexed form) to the device ring at `+0x30`. `0x823FB998` takes device/primitive/start vertex/vertex count in r3..r6; its game wrappers are `0x823ED140`, `0x8259E218`, and a call in `0x8259FB00`. `0x823FBD88` takes device/primitive/unused r5/start index/index count in r3..r7; all three identified callers set r5 to zero. Its indexed packet reads the active index buffer from device `+0x3094`. These are the first two draw hook identities with direct game call evidence; the native bodies remain unregistered pending an Afro field and runtime exactness audit. Sibling routines `0x823FAED8`, `0x823FB3C8`, `0x823FC1D8`, and `0x823FC658` need separate call-shape checks before matching the remaining draw hooks.

`tools/afro_pm4_scan.py` locates PPC immediates that may be PM4 packet opcodes. It only supplies a shortlist. `0x823658B0` and `0x82367D68` construct `0xC0032200` packets, but their first argument accesses `+0x10` of a command buffer object; neither is yet identified as a public draw entry. Their direct caller lists are empty within `0x82340000..0x82380000`; callers may lie elsewhere, dispatch indirectly, or be absent. `0x82345A08` writes constant packets and is not a draw entry. `tools/afro_data_refs.py` finds pointers to both packet writers at `0x82125718` and `0x821257E0`, within the executable's function/unwind metadata table. Those records establish function boundaries, not dynamic calls.

Next gates: audit the mapped draw and resource native bodies against Afro's API state and presentation fields, identify the remaining shader/texture entry points, then enable a small verified hook set. Run PC exactness verification on each enabled path before a new unelevated Ryujinx comparison. No PC/emulator profile qualifies a hand-written ARM native.

`tools/afro_xdk_calls.py` counts direct PPC branches into `0x82340000..0x82380000` from outside that range and reports their enclosing generated function starts. This misses indirect calls and cannot identify an API from call frequency alone. The wrapper block at `0x823E7C08..0x823E82D8` supplied independent call-shape evidence for seven more declarations:

| `D3DDevice_CreateIndexBuffer` | `0x82354788` | `0x823E8088` forwards length, usage and format, forces pool zero; entry encodes resource type 2 and index format. |
| `D3DDevice_CreatePixelShader` | `0x8234AE68` | `0x823E8150` forwards a microcode pointer and stores the returned shader; the entry builds a compact shader header. |
| `D3DDevice_CreateVertexShader` | `0x8234B2D0` | `0x823E80F0` forwards a microcode pointer; the entry builds an 872-byte vertex-specific header and copied microcode. |
| `D3DDevice_CreateVertexDeclaration` | `0x8234B820` | Scans 12-byte elements until stream `0xFF`, allocates `56 + 12*n` bytes and delegates initialization to `0x8234B730`. |
| `D3DDevice_ClearF` | `0x82370500` | Reads viewport `+0x3168`, scissor and tile targets; clips a 16-byte rectangle and emits clear PM4 packets. |
| `D3DDevice_Clear` | `0x82370C70` | Builds a whole-target rectangle from the active surface if none is supplied, then calls `0x82370500`; both game wrappers `0x823E7DB8` and `0x823E7ED0` use it. |

`tools/afro_hook_anchors.py --apply` moved these seven declarations; 32 individually traced non-table anchors were checked at this checkpoint. The `0x823658B0` and `0x82367D68` packet writers accept a command-buffer object whose write cursor is at `+0x10`, so they are lower-level packet constructors, not safe substitutes for the inherited draw hook signatures. Native hook registration stays off.

The PC sampler's two largest guest symbols, `0x823646F0` (6,750 samples) and `0x823631E8` (3,268), are on the GPU fence wait path. `0x823631E8` takes device in r3, fence in r4, blocker type in r5 and no-kick in r6; it reads the completed-fence pointer at device `+0x2A90`, the queued fence at `+0x2A9C`, and the reentry guard at `+0x33B0`, then polls through `0x823646F0`. Resource destruction and KickOff call it with different blocker types. This proves the inherited `BlockOnFence_hook` identity and moves its declaration to `0x823631E8` (33 non-table anchors). The native body remains unregistered; sampler counts measure PC time waiting for GPU progress and are not console speed data.

The `0x8234A810/0x8234A8F0` pair that many game routines call writes vertex/pixel float constants directly to device storage. It is not a draw path or a texture setter. The initial PM4 immediate scan's many `0x2200` hits also include register constants; its literal mode now reports only candidate words with top byte `0xC0`, which still need instruction-level validation. The texture setter is `0x82358098`: it takes device/sampler/texture in r3..r5, reads the texture's fetch constant at resource `+0x1C..+0x30`, writes the device texture slot indexed from `+0x3100`, and tags the prior texture with a fence. It has 22 direct callers, including the game wrapper at `0x823E82D8`. The native declaration now uses this entry; native behavior remains unregistered pending exactness.

`0x8234B6A0` is the five-instruction SetVertexDeclaration body: it stores r4 at device `+0x2E2C`, sets the pending-state bit in the device's 64-bit word at `+0x10`, and returns. It follows the default declaration initializer at `0x8234B610`; the corresponding native declaration now uses this address. The immediate scan's `--memory` option includes PPC load/store offsets so field references like `+0x2E2C` can be found directly.

`0x8234BC48` is SetShaderGPRAllocation: it takes device, flags, vertex count and pixel count in r3..r6, updates device `+0x2AA8`, and writes the `0xC0013F00` register packet. API state initialization calls it with three zero arguments. The native declaration is mapped, but the body still needs a field and packet-equivalence check.

`0x82345A08` is SetSurfaceClip: SetScissorRect at `0x82348490` passes four clipped coordinates in r4..r7, and the function writes scissor or per-tile clip packets to the device ring. The other nine direct callers are clear, resolve or state paths. It does not change the device's persistent clip fields; the native renderer's empty hook is appropriate for this packet-only helper, pending a runtime check.

`0x82345880` is ResetAllState: r4 suppresses its initial packet sequence, then it reapplies the clip and screen extent mode and sets the five 64-bit pending masks at device `+0x00..+0x20` to all ones. Present, tiling and resolve code call it. Its companion `0x82345978` is SetSurfaceInfo: it reads the surface's format word at `+0x18`, writes device surface info at `+0x2880`, marks pending masks, copies the default scissor at `+0x3184..+0x3190`, and tail-calls SetViewport. These identities map their native declarations, still unregistered until body equivalence.

The mode helper called by ResetAllState and API initialization is `0x8235A600`, SetScreenExtentQueryMode. It inserts r4 in bits 12..13 of device `+0x2AA4` and writes the mode register packet. Its native declaration is mapped; the native body writes the same field but omits the packet for the deko3d path.

Resource reference counting is another independent cluster. `0x823542A0` atomically increments resource `+4` and returns the new count; `0x82354318` decrements the same word and calls `0x82353B40` at zero; `0x82354400` reads the resource type from the low header bits and refines texture type from a second header word. These identify AddRef, Release, Destroy and GetType, respectively. Their declarations now use Afro addresses (37 non-table anchors). The Release call inventory includes 108 direct branches from game and XDK code, so this cluster is reached in the PC baseline. Registration and native resource lifetime behavior still need verification.

`0x82353D68` is the nine-argument resource lock worker: it tests the resource header and use flags, obtains device and physical addresses, and blocks on the fence when needed. `0x82354060` atomically removes the lock-count increment `0x100` and flushes the formerly locked ranges. The native `LockResource_hook` and `D3D_UnlockResource_hook` declarations are mapped. Direct lock wrappers for different resource types still need call-shape checks, so no wrapper was guessed from adjacency.

Afro gamma code `0x82349648` calls `0x823585D8`, which reads 256 samples per RGB channel from a 1536-byte ramp; `0x82349730` calls `0x823586C0`, which reads 128 base/delta pairs per channel from the same sized input. These establish SetGammaRamp and SetPWLGamma. Both write the corrected ramp at `+0x3A9C` and use pending pointer/flag `+0x5D90/+0x5D94` and display dirty word `+0x4144`. Native code still had Katamari's `+0x56E4/+0x56E8/+0x412C`; those were corrected. Native SetFence's `+0x5404/+0x3A30` reads were also corrected to Afro `+0x541C/+0x3A48` from `0x82362A08`. These fields have direct PPC evidence; the native gamma math still needs exactness comparison. The checked non-table declaration count is 41; hooks remain off.

Afro's tiling setup at `0x8236BFA0` writes rectangle count at `+0x31CC` and copies each 16-byte rectangle to `+0x31D0` onward; the previous native `+0x31C8` overlapped the fifth bound surface. It writes the extent at `+0x337C/+0x3380`, the clear color at `+0x3390`, clear depth/stencil at `+0x33A0/+0x33A4`, selected surface at `+0x31B4`, and tiling phase 2 at `+0x31B0`. End tiling at `0x8236C660` reads the extent and clear values from those same fields. The inherited native tiling paths were corrected to these offsets, including removal of two writes that clobbered extent_x. `0x8236BFA0` takes more arguments than the inherited four-argument BeginTiling hook, so its declaration remains unmapped. The PPC tiling predicate checks byte `+0x2F9B` (`0x8235ED28`, `0x8236C238`); native code previously read Katamari's `+0x2F93` and now reads the Afro byte. These are static fixes in hooks that remain disabled; no runtime equivalence or visual comparison has been claimed.

Presentation initialization at `0x8236E318` calls `0x82357D78` with width, height, format, multisample and surface-parameter arguments; the returned surface goes to the automatic back/depth slots. The CreateSurface declaration now names that generated start. Present at `0x8236DB28` calls `0x82371698` with the D3D resolve argument shape; the Resolve declaration now names that start. Present saves its viewport from `+0x3168`, and passes `device + 0x3548` as Swap's third argument. The inherited native Present body used `+0x3160/+0x3530`; these were corrected. The 21 non-table anchors remain declarations only, with native hook registration off.

The resource header routine `0x823570A8` loads 16-bit format records from `0x820E74C8` (`format & 0x3F`, doubled); Resolve `0x82371698` independently references the same table. Its physical allocation wrapper at `0x8240C418/0x8240C4A0` reads the no-large-pages word at `0x828AE868`. Both inherited global addresses were replaced. Hardware initialization `0x8236E8C0` copies a qword from `0x828AE7E0` to device `+0x2A80`.
